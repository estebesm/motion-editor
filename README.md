# Генератор обучающих motion-видео

Из текста урока — готовый ролик: ИИ-режиссёр придумывает кадры (списки, схемы, сравнения, скриншоты), диктор Gemini
озвучивает, Remotion рендерит. Плоский моушн-дизайн: кинетическая типографика, морфинг форм, плавная камера.
Всё на русском, шрифт Dela Gothic One (или свой).

## Установка

Проверено на macOS (Apple Silicon). На Linux работает так же, команды установки — через свой пакетный менеджер.

### 1. Обязательно

| Что | Зачем | Как поставить |
|---|---|---|
| **Node.js 23.6+** | движок (TypeScript запускается напрямую, без сборки) и рендер Remotion | `brew install node` |
| **ffmpeg + ffprobe** | озвучка, вырезание фона логотипов, превью файлов, звуки, сведение | `brew install ffmpeg` |
| **Ключ Gemini API** | ИИ-режиссёр, озвучка (Gemini TTS), проверка озвучки распознаванием речи | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
| **Интернет** | Gemini; при первом запуске — npm-пакеты, Chrome для рендера (Remotion скачивает сам, ~450 МБ), библиотека звуков с Openverse | — |

```bash
git clone https://github.com/estebesm/motion-editor.git
cd motion-editor
echo "GEMINI_API_KEY=ваш-ключ" > .env
./run.sh            # первый запуск сам поставит npm-зависимости (engine/node_modules, ~1 ГБ)
```

Проверить, что всё работает, — собрать пример урока без озвучки. Gemini при этом не вызывается, но ключ в `.env`
всё равно должен быть. Займёт около минуты, первый раз дольше (скачивается Chrome):

```bash
cp -r examples/урок-резервные-копии videos/
./run.sh --auto --video=урок-резервные-копии --draft --без-звука
# → videos/урок-резервные-копии/outputs/урок-резервные-копии (без звука).mp4
```

Ограничения Gemini: у бесплатного ключа дневной лимит озвучки. Когда он кончается, генератор сам переходит на
следующую модель озвучки, а уже озвученные фразы берёт из кэша (`videos/<имя>/.project/tts/`).

### 2. Необязательно: звуки лучше

Без этих инструментов звуковые эффекты всё равно есть: движок сам берёт записи из `sfx/library/` и сводит их
(см. «Звуки»). Инструменты ниже делают отбор и сведение точнее.

**earshot** — «слушает» звуки и выбирает лучшие, сравнивает звук ролика с профессиональными
([github.com/Leonxlnx/earshot](https://github.com/Leonxlnx/earshot), MIT). Нужен Python 3.10+. Ставится в `tools/`,
движок находит его там сам:

```bash
brew install python@3.12
git clone https://github.com/Leonxlnx/earshot tools/earshot
python3.12 -m venv tools/.venv
tools/.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu   # CPU-версия, без CUDA
tools/.venv/bin/pip install -e tools/earshot
```

При первом отборе earshot скачивает модели (~1 ГБ в `tools/earshot/.cache`) и думает несколько минут. Дальше всё берётся из кэша.

**real-sfx** — скилл Claude Code, сводит эффекты из вашей собственной библиотеки записей поверх чистого голоса.
Публичной ссылки нет: папку скилла нужно получить у владельца и положить в `~/.claude/skills/real-sfx`.
Затем подключить свою библиотеку звуков и поставить ffmpeg с фильтрами `rubberband` и `drawtext`:

```bash
brew install ffmpeg-full             # движок сам берёт его из /opt/homebrew/opt/ffmpeg-full для real-sfx
cd ~/.claude/skills/real-sfx
python3 scripts/setup.py init --library main="/путь/к/звукам" --uisfx --index
python3 scripts/setup.py check
```

Если real-sfx нет (нет файла `~/.claude/skills/real-sfx/library_index.json`), этот шаг пропускается без ошибок.

### Если что-то не так

- **«Нет GEMINI_API_KEY»** — нет файла `.env` в корне репозитория или в нём нет строки с ключом.
- **«Нужен Node.js 23.6+»** — `brew upgrade node`.
- **Рендер долго стоит на «Сборка проекта»** при первом запуске — Remotion скачивает Chrome, это бывает один раз.
- **Звуки пропущены** — Openverse недоступен. Ролик соберётся без эффектов; в следующий раз библиотека докачается.
- **Собрать библиотеку звуков заново** — удалите `sfx/library/`.

## Структура

```
run.sh
.env                       ← GEMINI_API_KEY=...
examples/                  ← пример урока (скопируйте в videos/)
videos/                    ← ваши видео (в git не попадают)
└── <название видео>/
    ├── scenario.txt       ← текст видео
    ├── prompt.txt         ← настройки и пожелания (необязательно)
    ├── sources/           ← картинки, видео, музыка
    └── outputs/           ← готовые версии видео
engine/                    ← код генератора
sfx/library/               ← библиотека звуков (скачивается при первом запуске)
tools/                     ← необязательные инструменты (earshot)
```

## Как сделать видео

1. `./run.sh` → **Создать проект**: название, голос, манера, цвета, динамика, кнопка, пожелания.
   Появится папка `videos/<название>/` с `prompt.txt`.
2. Вставьте текст в `scenario.txt`, положите файлы в `sources/`. Называйте их по смыслу:
   «экран настроек.png», «логотип.png», «запись экрана: создание папки.mp4». По названию (и по самой картинке)
   ИИ решает, где файл показать и как: как есть, с наездом камеры или в рамке телефона (для записей экрана).
3. `./run.sh` → **Начать генерацию видео** → выберите видео. Дальше без вопросов:
   всё берётся из `prompt.txt` (если его нет — настройки по умолчанию).
4. Готовое видео появится в `videos/<название>/outputs/`. Повторная генерация — новая версия (`-v2`, `-v3`…).

**Свой сценарий-раскадровка.** Если в `scenario.txt` есть сцены «## Тип», генератор берёт его как есть, без ИИ-режиссёра:
каждая строка — «фраза диктора → надпись на экране». Типы: Текст, Картинка: <файл>, Список, Шаги, Схема, Сравнение,
Важно, Финал: <логотип>. В Списке, Шагах и Схеме первая строка — заголовок (центр), дальше пункты. В Сравнении «А:» и «Б:» —
две стороны. `*слово*` — выделение, `[иконка]` — иконка пункта. Пример — `examples/урок-резервные-копии/scenario.txt`.

Посмотреть раскадровку без озвучки и рендера: `./run.sh --auto --video=<название> --plan-only`.
Она сохраняется в `.project/plan.json`. Его можно поправить руками, и следующая генерация возьмёт исправленную версию.

## Как ИИ работает с текстом

1. **Режиссёр** (режим `Текст: адаптировать`, по умолчанию) считает scenario.txt материалом с фактами,
   а не текстом для чтения. Сначала он придумывает видео — схемы, сравнения, списки, записи экрана,
   типографику, — и только потом пишет реплику диктора под каждый кадр: узлы схемы звучат по порядку,
   логотип — когда называют бренд. Все факты и предупреждения сохраняются, новых оценок не добавляется
   (это проверяется автоматически).
   Для диктора делается отдельная версия текста: латиница и числа — кириллицей (Excel → Эксель).
   Своё произношение задаётся в prompt.txt строкой `Произношение:`.
   В режиме `дословно` текст не меняется: он делится по предложениям, и раскадровщик подбирает сцены под него.
2. **Текст в кадре — структура, а не субтитры.** У каждой сцены есть тезис: законченная мысль, понятная
   без звука и передающая полный смысл реплики. Он держится всю сцену, а акцентное слово подсвечивается,
   когда диктор его произносит. Под тезисом может быть одна дополняющая строка. Перечисления идут
   списком или схемой: пункты появляются по одному и остаются, разные вещи не склеиваются в один пункт.
   Заголовок списка или схемы сначала стоит крупно по центру, а к первому пункту уезжает наверх,
   поэтому тексты не накладываются. Подписи не повторяют то, что уже видно на логотипах.
   Паттерны появления: плашка-шторка, подъём из-под маски, буквы «выпрыгивают», шторка с яркой полосой.
   Переходы — плашки, вертикальные полосы, круг, наезд со вспышкой, «смаз» камеры.
   Логотипам вырезается однотонный фон; в финале — логотип бренда, если он есть в sources.
3. **Озвучка** проверяется распознаванием речи: если диктор сбился (повтор, зачитал инструкцию,
   перешёл на английский) — фрагмент переозвучивается.

## prompt.txt

Строки «Ключ: значение», варианты подписаны в комментариях прямо в файле. После строки `Пожелания:` —
свободный текст. Если менять только голос, цвета или качество, раскадровка остаётся прежней;
если поменять сценарий, пожелания или файлы — ИИ составит новую.

Фирменный стиль: `Акцент: #3366FF, #FFB800` (два цвета — акцент и второй для градиента), `Фон: #1C1B23`,
`Шрифт: Unbounded` или имя файла шрифта из `sources/` (.ttf/.otf) — ширины букв для подгонки текста считаются из файла.
Логотип-надпись (широкая картинка «Логотип …») в финале заменяет строку с названием.

## Звуки

`Звуки: да | тихо | нет` в prompt.txt. Три инструмента работают вместе:

1. **Openverse** — настоящие записи (только CC0: без атрибуции, можно в коммерческих роликах). Один раз
   скачиваются кандидаты в `sfx/library/` (авторы — в `CREDITS.md`; собрать заново — удалить папку).
2. **earshot** (`tools/`, необязательно) — добавляет кандидатов, сделанных кодом (пролёты, попы, блеск), «слушает» всех и оставляет
   лучших по описанию нужного звука. После рендера сравнивает звук ролика с профессиональными роликами.
3. **real-sfx** (скилл Claude Code `~/.claude/skills/real-sfx`, необязательно) — сводит эффекты поверх чистого голоса: точные кадры событий,
   эффекты уходят из-под речи, громкость по ролям; сам себя проверяет.

Где звучит: пролёт на склейке, поп на появлении пункта списка / узла схемы, блеск на логотипе, нарастание и удар в финале.
Затем мастеринг до −14 LUFS. Рядом с видео: `<имя>-звук.md` (оценки real-sfx и earshot, моменты, которые стоит
послушать) и `<имя>-эффекты.wav` (дорожка одних эффектов). Если real-sfx или earshot не установлены — эффекты
сводит сам движок.

Как поставить earshot и real-sfx — в разделе «Установка».

## Скриншоты и записи экрана

Положите их в `sources/` с понятными названиями: «экран настроек.png», «запись экрана: создание папки.mp4».
Сцена `## Картинка: <файл>` показывает файл как есть, с наездом камеры или в рамке телефона (вертикальные
записи экрана). ИИ-режиссёр сам ставит файл туда, где о нём говорит диктор.

`Качество: 4K` в prompt.txt — рендер 3840 × 2160 (чётче мелкий текст на скриншотах; рендер дольше).

Без озвучки (например, если кончился лимит Gemini): `./run.sh --auto --video=<имя> --без-звука` — тайминги слов
считаются по темпу речи, файл получает пометку «(без звука)».
